## 1. 결정된 사항 (2026-08-03 담당자 확인)

RUNBOOK을 쓰기 전에 확인이 필요했던 4가지가 모두 정리되었습니다. **아래는 "빠진 기능"이 아니라 "그렇게 하기로 정한 것"입니다.** 후임자가 고장으로 오해하지 않도록 RUNBOOK에 그대로 적어야 합니다.

### ① 문의처 — 문제 없음 ✅

`contact.email = 'sia.kim@luxrobo.com'` 은 **퇴사하지 않고 계속 근무하는 동료**의 주소입니다. 그대로 둡니다.

~~`contact.phone` 과 `contact.kakao.channelUrl` 이 비어 있는 것도 의도된 상태입니다.~~
→ **`channelUrl` 은 2026-08-05 에 채워졌습니다** (`https://pf.kakao.com/_BxixiUK`).
이제 꼬리말에 카카오톡 채널로 바로 가는 링크가 나옵니다. 검색 안내 문구는
주소가 비어 있을 때만 나오는 대비책으로 코드에 남아 있습니다.
운영 시간도 같은 날 **평일 10:00~17:00** 으로 바뀌었습니다.

`contact.phone` 이 비어 있는 것은 그대로 의도된 상태입니다.
**전화 문의는 운영하지 않습니다.** 후임자가 빈칸을 실수로 여기지 않도록
RUNBOOK 에도 적어 두었습니다.

### ② `/privacy` 개인정보처리방침 — 보류 ⏸️

담당자 판단으로 현재는 만들지 않습니다. `/apply` 의 `privacyNotice`(국외이전·만14세 미만 고지)가 실제 고지 역할을 하고 있습니다.

RUNBOOK에는 **"의도적 보류"로 한 줄만** 남깁니다. 빠뜨린 것과 판단해서 미룬 것은 다르고, 나중에 교육청이 요구할 경우 그 기록이 담당자를 보호합니다. 여기서 더 논하지 않습니다.

### ③ 공지사항 기능 — 만들지 않음 ✅

별도 공지 기능은 두지 않습니다. 알릴 내용이 생기면 **`config/competition.ts` 의 해당 문구를 직접 수정**하는 것으로 대신합니다.

⚠️ 이 결정 때문에 `CLAUDE.md` 171행의 인수인계 체크리스트에 있는 **"post a 공지"** 항목은 더 이상 유효하지 않습니다. RUNBOOK 작성과 함께 `CLAUDE.md` 에서 그 문구를 지우세요. 문서 두 개가 서로 다른 말을 하게 두면 안 됩니다.

### ④ 정원(capacity) 화면 표시 — 하지 않음 ✅

`categories[].capacity` 값(합계 100)은 **운영진이 응답 시트에서 직접 세는 기준값**으로만 씁니다. 사이트에 잔여 팀 수를 표시하지 않고, 시스템이 마감을 막지도 않습니다.

정원이 찼을 때의 마감은 **구글폼에서 해당 종목 보기를 삭제**하는 수동 작업입니다. 이것이 유일한 마감 수단이므로 RUNBOOK의 핵심 절차가 됩니다.

## 2. 제가 앞서 잘못 말한 것 (정정)

지난번 사이트 검토에서 **"시작 연도가 1998로 잘못 표시된다"** 고 했는데, **틀린 지적이었습니다.**

`config/competition.ts` 883행은 `{ value: '1999', ... }` 로 맞게 적혀 있고, `src/components/CountUp.tsx` 110행은 애니메이션이 끝나면 config 값을 글자 그대로 씁니다:

```ts
setShown(t >= 1 ? value : format(n));
```

제가 **올라가는 중간에 스크린샷을 찍었을 뿐**입니다 (1035 → 1998 → 1999). `38,675` 도 같은 이유입니다. 코드에 버그는 없습니다.

`CountUp.tsx` 는 오히려 잘 만들어져 있습니다 — 자바스크립트가 막혀도 완성된 숫자가 보이고, 동작 줄이기 설정을 존중하고, 화면 낭독기용 값을 따로 둡니다. 화면만 보고 판단한 제 잘못입니다.
