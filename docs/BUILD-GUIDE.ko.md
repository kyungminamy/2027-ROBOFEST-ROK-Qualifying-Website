# Part 1 · 개념 — 지금 무엇을 만드는 건가

코드를 쓰기 전에 이 그림이 머릿속에 있어야 합니다. 없으면 Claude가 하는 말을 이해할 수 없습니다.

## 웹사이트의 세 부분

```
   ① 브라우저                ② 서버                    ③ 데이터베이스
   (학부모 휴대폰)      (Vercel의 컴퓨터)            (Supabase)
        │                        │                          │
        │  "신청 페이지 줘"      │                          │
        ├───────────────────────►│                          │
        │◄───────────────────────┤  HTML을 만들어서 보냄     │
        │                        │                          │
        │  "이 신청서 저장해줘"  │                          │
        ├───────────────────────►├─────────────────────────►│
        │                        │   서버만 DB에 접근 가능   │  저장
        │◄───────────────────────┤◄─────────────────────────┤
        │   "접수 완료됐습니다"  │                          │
```

**핵심 원칙 하나만 기억하세요: 브라우저는 절대 데이터베이스에 직접 접근하지 않습니다.** 학생 개인정보를 다루기 때문입니다. 브라우저 → 서버 → DB, 항상 이 순서입니다. Claude가 "브라우저에서 바로 Supabase에 연결하자"고 제안하면 거절하세요.

## 도구별 역할

| 도구 | 역할 | 비유 |
|---|---|---|
| **Node.js** | 내 컴퓨터에서 웹사이트를 돌리는 엔진 | 자동차 엔진 |
| **Next.js** | 웹사이트를 만드는 틀 | 자동차 뼈대 |
| **TypeScript** | 코드 언어. 오타를 미리 잡아줌 | 맞춤법 검사기 |
| **Tailwind** | 디자인(색·여백·글꼴)을 코드로 지정 | 스타일북 |
| **Git** | 변경 이력 저장. **되돌리기 기능** | 게임 세이브 파일 |
| **GitHub** | Git 저장소를 인터넷에 보관 | 클라우드 백업 |
| **Vercel** | 실제 인터넷에 사이트를 띄워줌 | 서버 임대 |
| **Supabase** | 신청 데이터를 저장하는 DB | 자물쇠 달린 캐비닛 |

## 반드시 알아야 할 용어 8개

- **로컬(local)** — 내 컴퓨터. `localhost:3000`은 나만 볼 수 있는 연습용 사이트
- **배포(deploy)** — 인터넷에 올려서 남들도 보게 하는 것
- **커밋(commit)** — 지금 상태를 저장. **되돌아갈 수 있는 지점을 만드는 것**
- **푸시(push)** — 커밋을 GitHub에 올림. 푸시하면 Vercel이 자동 배포
- **터미널(terminal)** — 검은 화면에 명령어를 치는 곳. Claude Code가 여기서 돌아감
- **의존성(dependency)** — 남이 만든 코드 조각. `npm install`로 가져옴
- **환경변수(env)** — 비밀번호 같은 값. **절대 GitHub에 올리면 안 됨**
- **RLS** — Supabase의 자물쇠. 이걸 끄면 개인정보가 인터넷에 공개됨

# Part 2 · Claude Code 사용법 — 가장 중요한 부분

Claude Code는 코드를 대신 써줍니다. 하지만 **판단은 여전히 당신 몫입니다.** 초보자가 망하는 패턴은 정해져 있고, 대부분 아래 규칙으로 막을 수 있습니다.

## 규칙 1 — 커밋이 당신의 안전벨트다 ★★★

이게 제일 중요합니다. Claude가 잘 돌아가던 코드를 망가뜨리는 일은 **반드시 일어납니다.** 커밋을 해뒀으면 1분 만에 복구되고, 안 해뒀으면 하루를 잃습니다.

**습관:**
- 뭔가 하나 잘 되면 → 즉시 커밋
- 새 작업 시작 전 → 커밋
- 하루 끝 → 커밋
- **하루 10번 커밋해도 많지 않습니다**

Claude에게 이렇게 시키세요:
```
지금 상태를 커밋해줘. 메시지는 한글로 "종목 카드 목록 완성"처럼 써줘.
```

망가졌을 때:
```
방금 변경사항 때문에 사이트가 깨졌어. 마지막 커밋 상태로 되돌려줘.
```

## 규칙 2 — 한 번에 하나씩

**나쁜 예:**
> 홈페이지 만들고 종목 페이지도 만들고 신청 폼도 넣고 모바일 대응도 해줘

5개를 한꺼번에 받으면 뭐가 깨졌는지 알 수 없습니다.

**좋은 예:**
> 홈페이지 상단에 대회명과 날짜를 보여주는 히어로 영역을 만들어줘. 날짜는 config/competition.ts에서 읽어와.

→ 확인 → 커밋 → 다음.

## 규칙 3 — 눈으로 확인하기 전엔 끝난 게 아니다

Claude가 "완료했습니다"라고 해도 끝이 아닙니다. **반드시 브라우저에서 직접 봐야 합니다.**

매번 확인할 것:
1. `localhost:3000`에서 실제로 보이는가
2. 휴대폰 크기에서도 깨지지 않는가 (브라우저에서 F12 → 휴대폰 아이콘)
3. 한글이 깨지지 않는가
4. 링크를 눌러봤는가

## 규칙 4 — 에러는 통째로 복사해서 붙여넣기

**나쁜 예:** "에러 났어"
**좋은 예:** 빨간 글씨 전체를 그대로 복사해서 붙여넣기

Claude는 에러 메시지를 읽고 원인을 찾습니다. 요약하면 정보가 사라집니다. 화면 스크린샷을 붙여넣어도 됩니다.

## 규칙 5 — 같은 문제로 3번 실패하면 방향을 바꿔라

Claude가 같은 오류를 반복 수정하며 맴돌 때가 있습니다. 3번 시도해도 안 되면:

```
이 방법으로 3번 시도했는데 계속 안 돼. 접근 방식을 바꿔서
더 단순한 방법으로 다시 해줘. 왜 안 되는지 먼저 설명해줘.
```

또는 마지막 커밋으로 되돌리고 다르게 요청하세요.

## 규칙 6 — Claude에게 거절해야 할 때

초보자라도 이건 알아야 합니다. Claude가 아래를 제안하면 **거절하세요:**

| 제안 | 왜 거절 |
|---|---|
| 브라우저에서 직접 Supabase 연결 | 개인정보 유출 위험 |
| `.env.local`을 GitHub에 올리기 | 비밀키 유출 |
| RLS 정책을 `using (true)`로 | 데이터 전체 공개 |
| 로그인/회원가입 기능 추가 | 범위 밖. 유지보수 부담 |
| 날짜를 컴포넌트에 직접 쓰기 | config 파일에만 |
| 잘 되던 걸 "개선"하려고 대규모 수정 | 8/14 전엔 안정성이 우선 |

거절 문구:
```
그건 하지 말자. CLAUDE.md에 적힌 원칙에 어긋나. 다른 방법으로 해줘.
```

## 규칙 7 — 계획을 먼저 시키기

큰 작업은 코드부터 쓰게 하지 말고 계획을 먼저 받으세요.

```
신청 폼을 만들 건데, 코드 쓰기 전에 계획부터 알려줘.
어떤 파일을 만들고 각각 뭘 하는지 목록으로. 내가 승인하면 시작해.
```

## 규칙 8 — 이해 못한 코드는 설명을 요구하라

```
방금 만든 파일이 무슨 역할인지 초보자가 이해할 수 있게
비유를 들어서 설명해줘. 3문장 이내로.
```

전부 이해할 필요는 없습니다. 하지만 **"이 파일은 대충 무슨 역할"** 정도는 알아야 인수인계 문서를 쓸 수 있습니다.

## 규칙 9 — 매 세션 시작할 때

Claude Code는 대화를 새로 시작하면 이전 내용을 잊습니다. 새 창을 열면:

```
CLAUDE.md와 config/competition.ts를 먼저 읽고 시작해줘.
오늘은 [작업 내용]을 할 거야.
```

# Part 3 · 환경 설정 (Windows)

## 설치 순서

**1. Node.js**
[nodejs.org](https://nodejs.org) → **LTS 버전** 다운로드 → 설치 (전부 '다음')
확인: 터미널에서 `node -v` → `v22.x.x` 같은 게 나오면 성공

**2. Git**
[git-scm.com](https://git-scm.com) → 다운로드 → 설치 (기본값 유지)
확인: `git --version`

**3. VS Code** (선택이지만 권장)
[code.visualstudio.com](https://code.visualstudio.com) — 코드를 눈으로 볼 때 씁니다. 터미널도 안에 있어서 편합니다.

**4. Claude Code**

**PowerShell**에서 (프롬프트가 `PS`로 시작하면 PowerShell입니다):

```powershell
irm https://claude.ai/install.ps1 | iex
```

🔴 **설치 후 PowerShell을 완전히 닫고 새 창을 여세요.** 설치 프로그램이 PATH를 추가하지만, 이미 열려 있던 터미널은 그 변경을 인식하지 못합니다. 이 단계를 건너뛰면 설치가 성공했어도 `claude`를 못 찾는다고 나옵니다.

CMD를 쓰고 있다면 (프롬프트에 `PS`가 없음):
```batch
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

**WSL은 필요 없습니다.** 윈도우 네이티브로 완전히 지원됩니다.

**Claude Code는 유료 플랜이 필요합니다** — Pro, Max, Team, Enterprise. 무료 Claude.ai 플랜에는 포함되지 않습니다. 첫 실행 시 브라우저가 열려 Claude 계정으로 로그인합니다. API 키는 필요 없습니다.

문서: [code.claude.com/docs/en/setup](https://code.claude.com/docs/en/setup)

> **터미널이 계속 문제가 되나요?** Claude **데스크톱 앱**에서도 터미널 없이 Claude Code를 쓸 수 있습니다. PATH 문제로 첫날을 다 쓸 것 같으면 시간을 잃지 말고 그쪽으로 전환하세요. 결과는 같습니다.

## 터미널 여는 법 (Windows)

- **VS Code에서:** 상단 메뉴 Terminal → New Terminal (가장 편함)
- **단독으로:** 시작 → `Windows Terminal` 또는 `PowerShell`

## Claude Code는 어느 폴더에서 작업하는가

거의 모든 초보자가 여기서 헷갈리니 한 번만 정확히 읽어두세요.

**Claude Code는 실행할 때 터미널이 있던 폴더에서 작업합니다.** 폴더를 고르는 메뉴 같은 건 없습니다. 현재 디렉터리가 곧 연결 대상입니다. 그래서 순서는 항상:

```
1. 폴더를 만든다
2. cd로 그 폴더에 들어간다
3. claude를 실행한다
```

반대 순서가 아닙니다. `claude`를 입력한 시점의 폴더가 프로젝트 최상위가 되고, Claude는 거기서 `CLAUDE.md`를 찾습니다.

**프로젝트 폴더 만들기:**

```powershell
mkdir C:\Users\luxrobo\projects\robofest-qualifier
cd C:\Users\luxrobo\projects\robofest-qualifier
claude
```

전용 폴더 하나를 쓰세요. 다운로드 폴더나 바탕화면에 바로 만들지 마세요. 경로에 한글이나 공백이 있으면 문제가 생기니 **영문 경로**를 쓰세요.

현재 위치가 헷갈리면 `pwd`를 입력하면 폴더 경로가 나옵니다.

**나중에 작업을 이어갈 때는** 같은 폴더로 `cd`한 뒤 `claude`를 다시 실행합니다. 다른 폴더에서 실행하면 프로젝트를 찾지 못합니다.

## 첫날 최소 목표

터미널에서 이 세 개가 나오면 준비 끝입니다:
```
node -v          →  v22.x.x (또는 그 이상)
git --version    →  git version 2.x.x
claude --version →  2.1.x (Claude Code)
```

`claude`를 못 찾으면 순서대로: (1) 설치 후 터미널을 재시작했나요? (2) `claude doctor` 실행. (3) 그것도 없으면 시스템 설정 → 환경 변수에서 사용자 PATH에 `%USERPROFILE%\.local\bin`을 추가하고 터미널 재시작.

**첫날 여기서 막히는 건 정상입니다.** 실력 문제가 아니라 환경 설정이 원래 그렇습니다. Claude Code한테 에러를 그대로 붙여넣고 물어보세요.

## 【 Day 2 】 디자인 기초 + 홈페이지 뼈대

```
한국어 웹사이트용 기본 설정을 해줘.
- Pretendard 폰트 적용 (한글 가독성이 좋은 웹폰트)

- 모바일 우선(mobile-first) 반응형
- 색상 테마는 부산광역시교육청 느낌의 차분한 파랑 계열
```

# Part 5 · 반드시 겪게 될 문제들

| 증상 | 원인 | 해결 |
|---|---|---|
| `npm: command not found` | Node 미설치 or 터미널 재시작 안 함 | 터미널 껐다 켜기 |
| `port 3000 already in use` | 이전 서버가 안 꺼짐 | 이전 터미널에서 Ctrl+C |

# Part 6 · 절대 하면 안 되는 것

1. **`.env.local`을 GitHub에 올리기** — 비밀키 유출. 올렸다면 즉시 Supabase에서 키 재발급
2. **RLS를 끄거나 `using (true)` 정책 추가** — 학생 개인정보 전체 공개
3. **브라우저 코드에서 service role 키 사용** — 위와 동일
4. **커밋 없이 몇 시간씩 작업** — 되돌릴 수 없음
5. **개인 계정으로 도메인 등록** — 퇴사 후 회수 불가
6. **무료 Supabase로 운영** — 9월에 정지된 채로 접수 시작
7. **8/13에 대규모 리팩터링** — 마지막 3일은 안정화만
8. **확인 안 하고 다음 단계로** — 문제가 쌓이면 원인을 못 찾음
